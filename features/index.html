Features

Nerv is built for developers who own NVIDIA GB-series machines: people who train, serve and debug models, write GPU code, and run the systems around them. These are the things you can do on Nerv that you cannot do out of the box anywhere else. How each one works is on the System page.

Serve models that others cannot load

S2 is Nerv's inference engine, written for this hardware from the CUDA driver API up. Models load in under a second because every step is captured ahead of time as a CUDA graph. Prefill on Qwen3.8-27B runs ahead of vLLM at every prompt length we measured, and speculative decoding is decided on the GPU.

S2 is the only engine we tested that runs NVIDIA's own NVFP4 checkpoint of Qwen 3.8 Flash-Next on a single GB10, because it keeps the model's n-gram table on disk. Stock vLLM and Atlas ran out of memory or refused to load it, and every competing recipe that worked needed its own re-quantised checkpoint.

Everything else you already use keeps working. PyTorch and your own CUDA code run unmodified, and a notebook that allocates too much GPU memory gets an out-of-memory error at its limit instead of taking the machine down.

Use every GPU and core you own

With axon, a program uses a GPU in another machine as if it were installed locally, with no rebuild and no code changes. That works for CUDA, Vulkan and OpenGL, across GB10s, and even to an AMD card in a Windows PC. Two DGX Sparks on one cable behave as one system: axon ships a drop-in libnccl.so.2, so multi-GPU programs run collectives across both machines, with a 20 KiB all-reduce in about 14 µs and bit-identical results on every rank.

Nerv also speaks 9P2000.L, which means you can run your programs on the cores of another Nerv computer to increase performance or save power. And axon top tells you where every piece of work actually ran.

Reach your machines from anywhere

Plexus connects your laptop to the Sparks at home or in the lab, wherever you are. It punches through NAT on both ends and connects directly over WireGuard, falling back to a relay that sees only ciphertext when no direct path exists. Machines are known by identity rather than address, so a laptop that sleeps, roams or changes networks reconnects as the same peer.

Access is a grant you control. Give a collaborator access to one machine, let it expire on its own, or revoke it and watch their session end. You host it yourself, and nothing about your fleet passes through anyone else.

Install anything

The base system is built on musl, but you are not limited to what Nerv builds. dnf install reaches the whole Fedora package collection, and pip wheels, CUDA toolkits and vendor binaries run on a glibc runtime that sits beside the base without a container or a chroot.

Containers get a GPU by holding one socket and one library, never the host's device nodes or driver libraries. A driver upgrade does not break your images, and a container cannot reach past its GPU allocation.

Update without fear

Every update is a new generation beside the one you are running, and the machine only switches to it after it has booted. If an update breaks the boot, the machine falls back to the last generation that worked, with nobody present. Your Spark in the lab stays reachable even when an update goes wrong.

You always run the newest kernel and the newest NVIDIA driver, and you get them within days of release, because rolling back is cheap. The disk unlocks itself from the TPM, so a remote machine reboots straight back onto the network without anyone typing a passphrase.
