Platforms

Nerv targets the unified-memory GPU workstation. Three targets are built from one source tree, each with its own kernel configuration and CPU tuning.

gb10

The primary target. NVIDIA GB10 on aarch64, with CPU and GPU sharing one memory pool. The DGX Spark is the machine Nerv is developed against; the GB300 and GB20 laptops are the same class of part and the same target.

Unified memory changes what the operating system is responsible for. The GPU arena and the page cache are the same pool, so reserving device memory is zero-sum against the filesystem cache, and a resident GPU process fragments the allocator for every process after it. Both are distribution-level problems, and both are what axon exists to solve. The arena is reserved on the kernel command line, before anything has had a chance to fragment memory.

strix-halo

AMD Strix Halo on x86_64, with a Radeon 890M and the same unified-memory arrangement. The HP ZGX and Z2 Mini G1a are the desktop machines in this class. This is the target Nerv is currently validated on.

The accelerator boundary is the same boundary; the vendor stack behind it is not. Keeping both targets in one source tree is what stops that boundary from quietly becoming an NVIDIA-shaped interface.

wsl2

Nerv as a WSL2 distribution on whichever architecture the Windows host is. There is no kernel package — Microsoft supplies the kernel — and the GPU is reached through the host driver bridge.

This is the target that makes the rest usable from a machine you already own, and it is the cheapest way to look at the system without reinstalling anything.
