The network is the install medium

Nerv does not install from a USB stick. The installer is a server you run on a machine you already have, and it provisions every other machine over the network. A target powers on, netboots a signed image, and installs itself.

Three programs, one name

Piece Runs on Job
bootstrap WSL2, Fedora, Nerv Fetch the server binary and verify its signature. Nothing else.
server the same box Version broker, boot source, caching mirror, live view of every client.
target the machine being installed The install itself, attended through a TUI or unattended.

The server binary is static musl with no host dependencies, so the same binary runs on WSL2, a Fedora box, or Nerv. The bootstrap that fetches it is short enough to read in full before running, and it verifies what it downloads against a public key embedded in the script itself.

The netboot artifact is a UKI, the same artifact class an installed slot boots. There is no separate live image to keep in step with the real system.

What the server does that a file server cannot

It holds several generations and decides which one each client gets, so one machine can take generation N+1 while the rest stay on N. It proxies the package mirror, so installing eight machines fetches each package once. It shows a live list of every target: hardware identity, chosen generation, current phase, progress, and the tail of that client's log.

Reporting runs from client to server only. The server offers a manifest and bits and issues no commands, so it cannot drive operations on a machine that has already booted.

Upgrading is the same operation

Netbooting a machine that already runs Nerv does not mean wiping it. It composes into the inactive btrfs slot, through the same code path and the same boot-counted rollback as a local update. The rare frightening operation and the routine one are the same operation, which is what keeps the frightening one from rusting.

A live USB remains the rescue path, and slot management stays available directly. The network installer is a new front end onto the same phases.

Building it yourself

Builds run on a development box and never on the target hardware, in a pure-musl chroot. geofront composes the chroot from the local repository, builds in it, and publishes back. A QEMU image needs no hardware at all.

build
# compose a rootfs image and boot it under QEMU/KVM
tools/nerv-mkimage --platform qemu-aarch64 --smoke
tools/nerv-qemu --smoke

# build a single package
geofront build packages/core/nerv-dash.spec
geofront --dry-run packages/core/nerv-dash.spec   # resolved plan, touches nothing
geofront --keep    packages/core/nerv-dash.spec   # keep the buildroot to debug a failure

Nerv tracks the newest upstream release of everything and does not pin to old versions. Bumping a package means updating Version: in the spec and rebuilding; geofront stages the new source itself.
