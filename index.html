What it does Install

Run your GPU program on a computer you are not sitting at.

Start a CUDA program here and it executes on the GPU in another machine. Same binary, not rebuilt, not containerised. The machine holding the GPU does not have to be running Nerv, or even Linux. A dispatched kernel has run on a remote A800 and returned results bit-identical to native.

How axon does this →

50% more tokens per second than vLLM on Ubuntu.

S2, the inference engine, is part of the image. Not a container and not a Python stack. Models are compiled ahead of time against the silicon they run on, so the runtime replays prepared work instead of deciding what to do on every token.

S2 →

Up to 20% faster than Fedora or Ubuntu, on less power. Boots in four seconds.

Every package is built with LLVM and ThinLTO and tuned for the CPU it runs on, the allocator is mimalloc rather than glibc’s, and temporary files for compilation and the browser live in memory. You notice it unpacking archives, running scripts, compiling, and scrolling a terminal buffer.

System →

CUDA works unmodified, and so does dnf5.

The base is musl with a complete glibc layer beside it, so the NVIDIA driver, runtime and toolkit work on first boot and the Fedora package ecosystem stays one command away. rpm and dnf5 themselves are built pure-musl, which no other musl distribution ships.

System →

Ask the machine which files are actually yours.

atfield measures every byte against the image the system was composed from and the packages that own it, then asks you about whatever is left. It turns “why is this disk full” and “move me to the new machine” into questions with recorded answers.

atfield →

Harder defaults that stay out of the way.

musl with mimalloc gives every process guard pages, randomised allocation and encrypted free lists. Control-flow integrity, stack protection and position-independent executables apply to the whole system, because one compiler built all of it. A bad update costs one reboot, because updates install into the slot you are not running.

What it is

A complete operating system rather than a distribution assembled out of someone else’s decisions. Nerv builds its own base from upstream source: the C library, the allocator, the compiler, the init system, the shell, the text tools and the package manager. Nothing underneath it is waiting on another project’s roadmap.

What that base feels like is a modern Unix with the GNU userland left behind. The text tools are Rust uutils, the console renders properly at high DPI and in truecolor, privilege escalation is doas, and the interactive shell is put together from the tools people actually reach for. None of it breaks scripting, because /bin/sh is still a POSIX shell that behaves the way scripts expect. Underneath, everything is compiled against musl with mimalloc using LLVM, and a glibc layer sits alongside it so CUDA, Python wheels and vendor binaries run without anyone having to think about the arrangement.

What you are allowed to do with it

Owning the whole base means owning its licensing, and Nerv is built so that no GPL-3 package is needed to boot a machine. The core is MIT, 0BSD, BSD and Apache, alongside the GPL-2 kernel and LGPL-2.1 libraries, none of which carry the clause that matters here.

The clause that matters is GPL-3 section 6. It obliges anyone shipping object code inside a user product to hand over whatever is needed to install a modified version. Secure Boot with kernel lockdown is precisely the restriction that triggers it, so a signed, locked-down boot chain and a GPL-3 runtime pull against each other. That is a real problem for anyone putting an operating system on hardware they intend to ship, and it is usually discovered late, by a lawyer.

Nerv does not manage that tension. It never creates it. A Nerv base can be signed, locked and shipped without the licence review turning into a redesign, and the handful of GPL-3 software people do want, rsync among them, remains one dnf5 install away as an ordinary choice rather than a structural commitment.
